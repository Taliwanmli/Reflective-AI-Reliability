# Contributing

This repository is in protocol development. Contributions should improve the research design, operational definitions, synthetic-data quality, documentation, or small offline validation tools.

## Before opening a change

1. Use an issue template to describe the research question or methodology change.
2. Keep claims prospective unless they are supported by versioned artefacts in this repository.
3. Explain how the change affects comparability, annotation, privacy, or reproducibility.
4. Run the validator and tests described in `scripts/README.md`.

## Data boundaries

Contributions must not contain real reflections, diary entries, direct messages, names, contact details, precise locations, account identifiers, clinical narratives, crisis content, or other personal data. Synthetic examples must be newly written, fictional, non-identifiable, non-clinical, and clearly labelled as synthetic.

Do not contribute private product code, prompts, screenshots, brand assets, production configuration, credentials, endpoints, roadmaps, or copied proprietary materials. If provenance is uncertain, do not submit the material.

## Methodology expectations

- Separate confirmatory hypotheses from exploratory analyses.
- Define the unit of analysis and score direction.
- Preserve condition isolation; avoid changing several manipulations at once.
- Document exclusions and deviations before examining outcomes where possible.
- Do not add fabricated results, citations, approvals, affiliations, or endorsements.
- Treat model-based evaluation as supplementary unless its validity is demonstrated.

## Pull requests

Use a focused branch and complete the pull-request template. By contributing, you agree that code is provided under MIT and that submitted documentation or synthetic research materials may be reused with attribution. You confirm that you have the right to contribute the material.
